# ClassicPixelSearch — Спецификация функций и Матрица QA / Регрессионных тестов

Документ описывает полный перечень функционала приложения **ClassicPixelSearch**, детальный анализ регрессии между версиями **v1.3.1-beta** и **v1.3.2-beta**, а также обязательный чек-лист тестирования перед внедрением любых изменений и фиксов.

---

## 1. Сравнение версий v1.3.1-beta и v1.3.2-beta (Анализ регрессии)

### Что произошло:
- **v1.3.1-beta (коммит `9676f6d`):**
  - **Цель:** Восстановить OneSearch в шторке All Apps (поиск приложений в лаунчере с подсветкой первого совпадения синим контуром и открытием по клавише `Enter`).
  - **Реализация:** В `LauncherStateService` при обнаружении фокуса или ввода в поле поиска Pixel Launcher (`ID_SEARCH_INPUT`), сервис на лету переключал `selected_search_engine` на `com.google.android.googlequicksearchbox`. При выходе возвращал обратно на `com.pixel.classicsearch`.
  - **Побочный эффект:** Виджет `OseWidgetView` в доке Pixel Launcher отслеживает системную настройку `selected_search_engine`. Каждое переключение приводило к перемонтированию виджета. Во время свайпов, медленных нажатий и жестов док мерцал (flicker), кратковременно показывал стандартную плашку Google или вовсе исчезал до завершения анимации.

- **v1.3.2-beta (коммит `c3408e5`):**
  - **Цель:** Полностью исключить мерцание и исчезновение виджета в доке при любых жестах и свайпах.
  - **Реализация:** В `LauncherStateService` удалили динамическое переключение движка поиска и урезали права Accessibility (`canRetrieveWindowContent = false`, оставлен только `TYPE_WINDOW_STATE_CHANGED`). Значение `selected_search_engine` заблокировано на `com.pixel.classicsearch`.
  - **Возникшая регрессия:** Так как `selected_search_engine` теперь не переключается на Google при открытии All Apps, сам Pixel Launcher не запускает алгоритм OneSearch для подсветки результатов внутри лаунчера при вводе текста. Вся обработка запроса уходит в `SearchTapActivity` только при явном подтверждении, а живая подсветка приложения в списке и быстрый запуск по `Enter` перестали работать.

## 2. Полный реестр функций ClassicPixelSearch

### Категория A: Интеграция с доком Pixel Launcher
| ID | Функция | Описание | Ожидаемое поведение |
|---|---|---|---|
| **DOCK-01** | Shizuku-интеграция | Предоставление разрешения `WRITE_SECURE_SETTINGS` в один тап | Статус меняется на «Подключено», запись в `Settings.Secure` доступна |
| **DOCK-02** | Монтирование в док | Подмена `selected_search_engine` на `com.pixel.classicsearch` | Стоковый поиск Google внизу экрана заменяется на ClassicPixelSearch |
| **DOCK-03** | Стабильность дока (Zero-flicker) | Удержание виджета при свайпах, тапах и скролле рабочих столов | Док не моргает, не пропадает и не перерисовывается в стоковый |
| **DOCK-04** | OneSearch Drawer Sync & Enter QuickLaunch | Поиск приложений в шторке All Apps при свайпе вниз | При вводе названия приложение подсвечивается и открывается по `Enter` |

### Категория B: Зоны нажатия (Touch Targets) и диспетчеризация
| ID | Элемент | Цель (Target) | Поведение по умолчанию | Возможности переназначения |
|---|---|---|---|---|
| **TAP-01** | Google "G" Logo | `TARGET_LOGO` | Открытие Google App (`SearchActivity`) | Стабильный запуск основного приложения Google |
| **TAP-02** | Поисковая строка (капсула) | `TARGET_SEARCH` | Поиск Google или поиск установленного приложения | Если введён текст приложения — мгновенный запуск `Intent.ACTION_MAIN` |
| **TAP-03** | Микрофон | `TARGET_MIC` | Голосовой поиск Google (`ACTION_VOICE_SEARCH`) | Переназначение на любое приложение или браузер + динамическая смена значка |
| **TAP-04** | Центральная кнопка | `TARGET_MIDDLE` | Gemini (`ACTION_GEMINI`) | Lens, AI Mode, ChatGPT, Perplexity, QR, Браузеры, Любое приложение + динамическая смена значка |
| **TAP-05** | Правая кнопка | `TARGET_AI` | AI Mode (`ACTION_AI_MODE`, `udm=50`) | ChatGPT, Perplexity, QR, Браузеры, Любое приложение + динамическая смена значка |
| **TAP-06** | Динамические иконки кнопок | `resolveActionIcon` | Авто-синхронизация значков кнопок с выбранным действием | Отрисовка нативного значка установленного приложения из `PackageManager` или векторного пресета (QR, ChatGPT, Perplexity, Браузер) |

## 3. Матрица регрессионного тестирования (Обязательный чек-лист перед релизом)

Перед подтверждением любого исправления или слиянием изменений, ОБЯЗАТЕЛЬНО проверяются все 5 блоков:

```
[ ] БЛОК 1: Целевой баг
    [ ] Воспроизвести условия бага до фикса
    [ ] Проверить, что в новой сборке баг полностью устранён

[ ] БЛОК 2: Док и жесты лаунчера (Критический путь)
    [ ] Свайп снизу вверх (открытие All Apps) — док не мерцает
    [ ] Свайп сверху вниз (шторка уведомлений / OneSearch) — док не пропадает
    [ ] Скролл между экранами рабочего стола — плавность, отсутствие артефактов
    [ ] Медленный тап и удержание на виджете — отсутствие мигания стокового Google виджета

[ ] БЛОК 3: Поиск и OneSearch QuickLaunch
    [ ] Ввод имени приложения в строке (например, "Telegram", "Калькулятор")
    [ ] Проверка подсветки найденного приложения
    [ ] Нажатие клавиши Enter на клавиатуре — запуск приложения без перехода в веб-поиск
    [ ] Ввод произвольного поискового запроса — открытие поиска Google

[ ] БЛОК 4: Кнопки быстрого доступа
    [ ] Тап по логотипу 'G' -> открывает Google
    [ ] Тап по микрофону -> запускает голосовой ввод / заданное действие
    [ ] Тап по средней кнопке -> открывает назначенный сервис (Gemini / Lens)
    [ ] Тап по правой кнопке -> открывает AI Mode / кастомное действие
    [ ] Проверка срабатывания тактильной отдачи (Haptics)

[ ] БЛОК 5: Смена темы и геометрии
    [ ] Смена темной/светлой темы устройства -> цвета виджета адаптируются
    [ ] Смена обоев рабочего стола -> палитра Monet обновляется
    [ ] Изменение слайдеров в настройках (Gap, Radius, Alpha) -> виджет мгновенно перерисовывается
```

## 4. Стратегия решения конфликта «Мерцание дока vs OneSearch-подсветка»

Причина конфликта заключается в том, что `OseWidgetView` в Pixel Launcher привязан к `selected_search_engine`. Если менять движок через `Settings.Secure`, лаунчер пересоздает вьюху.

**Рекомендуемое архитектурное решение для будущей версии:**
1. Не трогать `selected_search_engine` глобально во время жестов свайпа/тача на домашнем экране.
2. Внедрить селективную синхронизацию фокуса:
   - Если пользователь находится в шторке поиска (`All Apps`), лаунчер использует `SearchTapActivity`.
   - В `SearchTapActivity` уже реализован `findMatchingAppLaunchIntent(query)`.
   - Для возвращения визуальной подсветки приложений внутри самой шторки — настроить `LauncherStateService` так, чтобы он не переключал движок на уровне настроек, а инжектировал доступные действия или передавал фокус клавиатуры в нативный оверлей без сброса нижнего дока.
